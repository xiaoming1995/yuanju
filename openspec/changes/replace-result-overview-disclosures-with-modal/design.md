## Context

结果页的命盘总评、座驾和路况已按摘要优先组织，但其下方仍保留四个原生 `details` 折叠块。等级说明、路况说明、座驾依据和路况依据属于同一层级的深入信息；将它们堆叠在页面中会拉长概览区域，也使用户难以判断哪个说明与哪张摘要卡对应。

## Goals / Non-Goals

**Goals:**
- 让概览首屏只保留结论、座驾和路况摘要。
- 用一个可复用的模态框承载四类深入说明，并从对应摘要卡直接打开。
- 保留当前等级和道路高亮、全部算法证据及其既有文字。
- 支持键盘和移动端阅读。

**Non-Goals:**
- 不调整命盘等级、大运路况、证据或算法评分。
- 不新增 API、服务端状态或第三方组件库。
- 不将说明内容改写为新的命理解读。

## Decisions

### 使用单一受控模态框

`ResultPage` 维护一个当前说明类型状态：`grade`、`road`、`vehicle-evidence`、`road-evidence` 或空值。摘要卡中的入口只改变该状态，模态框依据类型渲染既有数据。单一模态框避免四套重复的焦点、滚动和关闭逻辑，也确保任一时刻只有一个深入内容层打开。

分别保留四个页内 `details` 被拒绝，因为它会继续占用页面纵向空间并造成当前的观感问题。

### 入口随摘要卡放置

等级和座驾依据入口放在座驾卡内；路况和路况依据入口放在当前路况卡内。专业依据入口仅在专业模式和对应证据存在时显示。移除概览网格后的支持说明区，避免页面中留下孤立的操作带。

### 对话框交互与响应式布局

模态框使用语义 `role="dialog"`、`aria-modal="true"` 和关联标题。关闭按钮、遮罩点击及 `Escape` 都可关闭；打开后焦点进入对话框，关闭后回到触发入口。桌面端采用居中、限制宽高的阅读面板；窄屏端保持近全宽并允许内容区独立滚动。背景页面在对话框打开时禁止滚动。

浏览器原生 `dialog` 未作为唯一方案，因为现有页面需要一致的遮罩、焦点恢复与移动端样式控制；使用 React 受控渲染和现有 CSS 更贴合项目模式。

### 不复制或改写证据内容

等级、道路说明和证据列表继续由现有 `VEHICLE_GRADE_GUIDE`、`ROAD_GUIDE` 与 API 返回的 evidence 数据生成。模态框只改变呈现容器，当前等级/道路仍按原逻辑高亮，避免改变任何评分语义。

## Risks / Trade-offs

- [模态框内容很长] → 限制面板高度，只有内容区滚动，标题与关闭按钮保持可见。
- [键盘用户失去页面位置] → 打开时记录触发元素，关闭后恢复焦点，并支持 `Escape`。
- [移动端遮挡底部内容] → 使用视口约束和安全内边距，不让模态框超出屏幕。
- [专业模式入口过多] → 仅在存在相关证据时显示对应入口，普通模式只显示等级和路况说明。

## Migration Plan

1. 以同一份结果数据替换页内 `details` 为入口按钮和模态框。
2. 在桌面、移动端和键盘交互下验证内容与焦点行为。
3. 回滚时恢复现有页内折叠渲染；不涉及持久化数据迁移。
