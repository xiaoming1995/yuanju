## Why

后台用户列表目前只有注册时间、来源、状态和累计起盘数，无法判断用户何时真正登录、最近是否使用产品，也缺少排查账号操作的时间线。网页邮箱与微信小程序共用用户体系后，管理员需要统一、准确且有边界的用户活动视图。

## What Changes

- 记录成功的网页邮箱登录、小程序微信登录、注册及账号绑定，区分“最后登录”和“最近活跃”；不从注册时间或 JWT 请求推测登录。
- 记录少量成功完成的核心业务行为：起盘、创建合盘、生成 AI 报告、更新个人资料；仅保存事件类型、渠道、时间和必要的记录引用。
- 记录管理员创建、禁用、解禁、重置密码和删除用户的操作人、目标与时间。
- 在后台用户列表显示最后登录和最近活跃时间，增加注册来源、状态、从未登录及最近活跃筛选和时间排序。
- 新增分页的用户详情活动时间线与概况，旧用户无历史事件时明确显示“暂无记录”。
- 为活动事件定义保留和用户删除时的清理规则；不追踪普通页面浏览、输入内容、命盘内容或报告正文。登录失败排查暂不纳入本次变更。

## Capabilities

### New Capabilities

- `admin-user-activity-insights`: 普通用户登录与关键行为的受控记录、后台用户筛选及详情时间线、管理员用户操作审计和事件生命周期。

### Modified Capabilities

无。

## Impact

- 后端数据库迁移、用户与管理员仓储层、认证及关键业务成功路径、管理员用户 API 和清理任务。
- 管理后台用户列表与详情页、管理员 API 请求层及相关测试。
- 现有用户认证响应格式和普通用户页面流程保持兼容；不引入新依赖。
