## Context

项目已有 Go 排盘与网页端，但尚无小程序项目。用户提供的展示稿包含「干支查询、查询历史、日历、我的」四个主画面及日期选择、命盘详情、节气标记、提示弹窗等局部状态。本轮目的是先看小程序前端效果，尚未授权真实账号、排盘或日历接口的接入。

## Goals / Non-Goals

**Goals:**

- 在微信开发者工具中直接运行一个独立的小程序界面原型。
- 复现展示稿的白灰卡片、金色强调、四柱色彩与三栏底部导航，并使主要操作有可见反馈。
- 让所有演示结果、历史与日历信息明确属于示例数据。

**Non-Goals:**

- 不实现真实排盘、账号登录、历史持久化或服务器同步。
- 不新增后端接口或修改现有网页端。
- 不提交微信平台审核或声明满足上架要求。

## Decisions

### 使用微信小程序原生项目

新增 `miniapp/`，使用 WXML、WXSS、JavaScript 和原生页面生命周期。当前只需要验证微信端界面，原生项目无需新增前端依赖，并可直接由本机微信开发者工具加载。曾考虑 Taro，但它会引入工具链与包管理，无法提高本轮静态原型的验证价值；正式业务移植时可重新评估。

### 页面和导航

底部三个页面分别是「首页」「日历」「我的」。首页通过顶部切换展示「干支查询」与「历史记录」，对应设计稿的前两张主画面。使用原生导航栏和小程序 tabBar，减少胶囊、安全区域适配误差。查询表单提交后通过 `navigateTo` 进入独立结果页，原生返回回到保留输入状态的首页；点击历史卡片仍打开详情弹层。

### 数据与状态

示例命盘、历史卡片与日历标记在小程序本地的演示数据模块中定义，不请求 `/api`。查询按钮把本次输入暂存于小程序内存并打开独立结果页；结果页区分「本次选择」和固定的「命盘示例」，避免暗示所选日期已被计算或保存。历史卡片删除仅改变当前页面内的演示列表，重新进入页面恢复。我的页显示未登录演示状态，不伪造身份。

结果页的「基本排盘」按网页端专业视图的字段顺序展示：日期列、主星、天干、地支、藏干、副星、星运、自坐、空亡、纳音、神煞。示例值由现有 Go 排盘引擎以固定公历 1990-01-01 01:00、男命、北京时间生成，再打包为本地数据；五行统计也来自同一结果。这样可核对网页端同一示例的字段和值，查询其他日期仍只改变「本次选择」区域。

固定示例还从同一次引擎结果导出命格名称、说明与 `natal_assessment.stem_guidance`。四柱卡片内直接显示「命格」标签和格名，后续核心结论卡展示说明，以及网页首屏的天干级「首取／扶抑可用／扶抑慎用」和同源的五行级扶抑喜忌；调候专用天干不混入扶抑可用列表。该区域继续标为示例命盘，查询输入仍不驱动实际计算。

### 视觉实现

全局 WXSS 维护颜色、圆角、阴影和文字规范；页面样式负责布局。日期输入使用小程序 `picker-view` 制作底部选择层，支持年份、月份、日期、时、分的演示交互；这不代表现有后端支持分钟排盘。日历月格以固定示例年月及前后月生成，节气与农历文字来自演示数据。

## Risks / Trade-offs

- **示例日期与命盘未实时计算** → 所有结果区域展示「演示数据」提示，正式接入时才定义真实算法与接口契约。
- **原生小程序与网页端分别维护界面** → 当前只用于视觉验证；后续正式版本需决定是否沿用原生实现。
- **开发者工具可能要求开发者登录或正式 AppID 才能手机预览** → 项目使用体验 AppID 供本机查看，并在交付时明确手机预览边界。

## Migration Plan

原型与现有服务隔离，没有数据迁移。移除 `miniapp/` 即可撤回，不影响网页与后端。

## Open Questions

- 视觉与交互确认后，正式版是否仍采用原生小程序实现。
- 正式版日期输入是否需要分钟精度；现有排盘接口只接收小时。
