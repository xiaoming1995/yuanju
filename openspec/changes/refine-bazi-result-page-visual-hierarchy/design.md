## Context

`ResultPage` 已同时承载总评、命盘座驾、当前路况、命格古人映照、大运趋势、判断依据、原局专业数据和 AI 解读。近期新增的模块分别使用自己的卡片、标题、标签和说明，导致首屏阅读路径被切割；`ResultPage.css` 也以多轮局部覆盖的方式叠加了相近的视觉规则。

本次只调整呈现层级与 CSS 组织，不改变命盘计算、接口数据、阅读模式语义或既有模态框交互。受众同时包含快速获得结论的普通用户与需要追溯依据的专业用户。

## Goals / Non-Goals

**Goals:**
- 建立稳定的三层阅读顺序：核心结论、当前状态摘要、深入阅读。
- 使首屏只承载可立即帮助决策的信息，减少同级标题、标签与卡片之间的竞争。
- 用统一的容器、标题和间距规则使座驾与路况在桌面端对齐、移动端连续阅读。
- 让专业模式复用相同页面骨架，仅增加已有的专业入口和数据密度。

**Non-Goals:**
- 不修改命格、用神、等级、路况或趋势算法及其文案含义。
- 不删除古人映照、判断依据、专业命盘和 AI 解读能力。
- 不引入 UI 组件库、插图资产或新的 API。

## Decisions

### 采用“结论驾驶舱 + 渐进阅读”信息架构

结果页的首个阅读区固定为：四柱与身份信息、核心扶抑结论、总评与当前阶段、座驾与路况摘要。趋势、原局依据、命格参考及 AI 解读按阅读深度位于其后。

这让用户先获得“本命基础如何、当下走在什么阶段、该继续看哪里”的答案。维持所有模块平铺在首屏被拒绝，因为它继续让辅助信息与结论争夺注意力。

### 将命格古人映照归入辅助阅读层

古人映照保留为独立、克制的参考段，移动到核心摘要和趋势之后；它不再出现在四柱标题与命盘总评之间。专业资料仍在专业模式显示。

古人映照并非即时判断依据，下移既避免首屏拉长，也降低用户把参考人物误读为个人结论的风险。

### 用完整信息带替代连续卡片堆叠

总评作为一个明确的结论带；座驾和路况保留为同一摘要网格中的两个并列面板；后续模块使用页面级区块、轻边界和固定垂直节奏组织。卡片内不再叠加次级卡片，标签只保留支持主结论的最少数量。

保留每个模块独立的大卡片被拒绝，因为它会进一步增加边框、底色和标题重复，无法形成“大气”的页面留白。

### 建立一套可复用的视觉令牌与响应式规则

结果页使用统一的内容最大宽度、区块间距、标题层级、弱分隔线、低对比标签和摘要操作样式。桌面端仅在摘要区使用双列并保持顶部对齐；窄屏按“结论 → 座驾 → 路况 → 深入阅读”的单列顺序排列。当前模态框仍独立于页面布局，保持其可访问性与内部滚动行为。

这次会优先收敛与总览相关的重复 CSS 规则，再补充需要的局部样式，而不是继续追加覆盖块。

## Risks / Trade-offs

- [首屏内容精简后，用户找不到专业信息] → 保留清晰的分段导航、专业模式入口与上下文模态框。
- [下移古人映照降低其曝光] → 保留明确的“命格参考”标题，并与主结论分开，避免误读。
- [不同数据完整度导致摘要高度差异] → 使用顶部对齐和内容驱动高度，不强制短卡拉伸。
- [CSS 收敛影响既有小屏样式] → 对桌面、窄屏、无座驾路况数据和专业模式分别进行视觉回归。

## Migration Plan

1. 先重排结果页 DOM 的页面级区块，并为摘要、辅助阅读和深入阅读建立稳定锚点。
2. 收敛总览相关 CSS，替换重复卡片与标签视觉规则。
3. 回归验证简单模式、专业模式、桌面和移动端；不涉及数据迁移。
4. 如需回滚，只恢复原页面 DOM 与 CSS 规则；接口和存储无需处理。
