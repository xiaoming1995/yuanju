## Context

`bazi_charts` 每次成功起盘插入一行；后台当前 `chart_count` 聚合现存行。用户可以删除命盘，活动事件又只保留 90 天，因此两者都不能作为永久累计次数。游客起盘没有用户归属。小程序用户可并入网页账号。

## Goals / Non-Goals

**Goals:** 累计已登录用户成功创建命盘的次数；后台清晰展示累计次数和现存数；账号合并后保留两边累计值。

**Non-Goals:** 追溯已删除的旧命盘、统计游客并在登录后追认、统计失败请求或合盘次数。

## Decisions

- 在 `users` 增加非空 `chart_query_count`，迁移时按现存 `bazi_charts` 回填。独立计数不会随命盘删除或活动事件清理减少。旧历史中已删除的命盘无证据可恢复。
- 在创建命盘的同一事务内增加归属用户计数；事务失败时两者都不计。重复成功插入同一生辰各算一次。使用事务中的现有用户更新，避免并发丢失。
- 小程序账户合并时将计数加到保留的网页账户，和现有命盘转移在同一合并事务完成。
- 管理员列表与详情 API 在保留 `chart_count` 的同时新增 `chart_query_count`。UI 将前者明确标为现存排盘，将后者标为累计查盘次数。

## Risks / Trade-offs

- 历史已删除命盘无法精确回填 → 文案说明迁移前计数至少包含现存记录，迁移后才完整累计。
- 已登录用户若保存失败则返回错误，避免返回成功却不累计；游客沿用无需保存也可查询的行为。

## Migration Plan

增加 goose 迁移，先新增计数字段并回填，再发布依赖字段的新代码。回滚可删除字段，但会丢失迁移后的累计值。
