## Context

首页由原生微信小程序的 `index.wxml`、`index.wxss` 和 `index.js` 实现。查询态自上而下是整条胶囊切换、表单卡、今日干支卡和最近记录卡；全局 `app.wxss` 为标题、卡片和主按钮提供相同的装饰语言。目前首页已经接入真实排盘与历史接口，日期精度为整点，且未登录时排盘会提示登录。工作区存在尚未提交的相关代码，因此实施时须以当前文件为基线，不覆盖这些业务改动。

## Goals / Non-Goals

**Goals:**
- 首屏突出出生日期、性别和排盘动作，今日干支与最近记录以更轻的层级呈现。
- 历史列表、日历及排盘结果保持易于进入，空历史与加载状态仍清楚。
- 保留金色品牌线索，同时提高文字、控件和状态的可读性。

**Non-Goals:**
- 不改排盘算法、登录门槛、API、本人命盘绑定逻辑或日历数据来源。
- 不将网页端或小程序其他页面纳入本次视觉重做。

## Decisions

### 1. 用轻量历史入口代替查询态的大胶囊切换

查询态顶部保留一处醒目的页面标题或表单标题，历史入口使用文字操作。历史态在内容起始位置提供带左箭头与文字的独立“返回排盘”按钮，置于历史标题之前；继续使用现有 `mode` 切换、`openHistory` 和 `switchMode` 逻辑。最近记录旁的“全部记录”仍指向同一历史态。相比保留整条切换并仅改变颜色，这能减少查询首屏一个大面积控件，同时让历史态的返回路径足够明显。

历史态用带圆形左箭头的返回操作与“我的排盘”标题建立清楚的阅读顺序，避免重复使用大面积按钮。历史卡片先展示名称和日期，再以四列浅底区域呈现年、月、日、时柱；底部将“设为本人命盘”和“查看详情”作为两个独立操作。已绑定的记录显示状态标签，解绑入口收在列表上方的状态行。卡片沿用首页左右边距，并减少阴影与大面积金色填充。

### 2. 首页局部样式优先，建立三层视觉权重

排盘区域为第一层：输入标签、完整宽度的日期触发器和单个高对比主按钮。今日干支为第二层：日期与三柱仍有清楚的分组，但减弱内外两层边框。最近记录为第三层：压缩垂直占用，以名称、四柱摘要和日期体现信息。首页局部覆盖标题、卡片、按钮样式；除非验证确有必要，不修改全局 `app.wxss`。

### 3. 用排版和留白代替重复装饰

首页去掉重复的标题金色竖条，降低卡片阴影与圆角的存在感；统一左右边距与区块间距。主按钮承担主要金色强调，性别选项使用安静的分段选中态，不与主按钮竞争。长备注、长记录名和窄屏文字必须折行或截断在各自区域内，不产生横向滚动。

### 4. 提示与数据语义保持准确

排盘说明压缩到输入附近，保留“公历”和“整点”的关键信息。今日干支若显示预置示例日期，继续由 `calendarPreview.title` 明确标识为示例；简化卡片脚注时，不把示例说成实时今日数据。保留未登录、加载、计算中和空历史的现有反馈。

## Risks / Trade-offs

- [去掉顶部双项切换后历史入口可能不明显] → 查询态顶部保留清晰的“历史记录”操作，并从最近记录区提供“全部记录”；历史态在内容起始处提供独立的左箭头返回按钮。
- [压缩卡片后窄屏内容拥挤] → 在常见和窄屏模拟器中检查四柱、日期、长备注与长名称，必要时允许次要文字换行。
- [首页局部样式覆盖全局组件产生意外效果] → 限定在 `.home-page` 作用域，并检查日期选择层、历史态和结果跳转。

## Migration Plan

仅发布小程序前端页面改动，无数据迁移。若视觉验收不通过，可回退本变更对应的首页 WXML/WXSS 局部修改。

## Open Questions

无阻塞问题；以“暖白底色、克制金色、排版优先”为本轮视觉基线，在实机截图验收时微调细节。
