## Context

当前 `wx.login` 只交换账号身份，资料接口分别保存昵称和头像；“我的”页支持主动编辑。微信头像选择与昵称输入需要用户分别操作。

## Goals / Non-Goals

**Goals:** 新建账号后立即引导选头像和昵称；两项完成时自动保存；用户可取消；老账号不重复弹出。

**Non-Goals:** 静默读取微信个人资料，或强制用户提供头像昵称。

## Decisions

- 登录服务向客户端返回 `is_new_user`，仅实际新建账号的登录打开引导。用服务端判断注册事件，避免依赖设备本地缓存或猜测创建时间。
- 首次引导复用现有资料编辑器，隐藏手动保存按钮。头像选中且 `input type="nickname"` 的 `nicknamereview` 事件确认审核通过后，才调用现有更新昵称、上传头像接口；手动打开编辑器仍使用保存按钮，允许单项修改。
- 资料保存失败时保持编辑器和已选内容，显示错误以便重试；取消关闭引导，不影响登录或后续主动编辑。

## Risks / Trade-offs

- 微信头像昵称仍需两次用户操作 → 界面明确说明，并将保存自动化。
- 两个现有资料接口分别提交，第二步失败可产生部分资料 → 保留选中内容和重试入口；后续资料读取以服务端值为准。
- 同一微信账号并发首次登录 → 仅数据库中实际创建身份的请求返回新建标识，其余请求复用该账号。
