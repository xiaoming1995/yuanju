## Context

小程序原型通过 `miniapp/tools/generate_demo_calendar.go` 调用 `github.com/6tail/lunar-go v1.4.6`，生成 2025—2027 年的静态日期标签。现有 `calendar.Lunar.GetZhiXing()` 已按月支、日支给出建、除、满、平、定、执、破、危、成、收、开、闭十二值，无需另写历法算法。

## Goals / Non-Goals

**Goals:**

- 每个预置日期都有与既有农历、干支同源的建除值。
- 日历选中日期卡和「每日干支参考」详情展示同一天的建除值及简短释义。
- 在数据缺失时显示未知状态，不臆造建除值。

**Non-Goals:**

- 不在月历每个日期小格标注建除，避免挤占农历和节气。
- 不新增黄历宜忌全套规则，不让建除值单独决定投资或搬家的事项提醒。
- 不改后端 API 或接入真实命盘。

## Decisions

### 复用现有历法库生成字段

在静态日历生成器中新增 `jianChu`，直接写入 `lunar.GetZhiXing()` 的结果。该方法与当前日历数据采用同一 `NewSolar(..., 12:00)` 日期对象；比在小程序端重写月支、日支与节令换月规则更容易保持一致。字段属于通用日期数据，不属于个人命盘数据。

### 把释义与个人判断分开

小程序端用一个十二项的展示字典提供简短字义说明。日历选中日期卡显示「建除十二值：危日」及一句释义；详情页独立卡片显示值、释义和十二值顺序。个人关系与事项提醒继续使用现有示例规则，不把单个建除标签转译为买卖或搬家结论。

## Risks / Trade-offs

- [建除有不同流派或解释] → 计算沿用项目已固定版本的 `lunar-go`；释义只概述字义，不宣称完整择日宜忌。
- [静态日历范围有限] → 缺少日期数据时显示「暂无建除数据」，不回退为猜测。
- [用户将建除误认成个人喜忌] → 在详情页注明它是通用日期标签，与命盘关系分开展示。

## Migration Plan

重新生成小程序本地 `calendar.js` 并随原型一起加载，无数据库迁移。撤回时移除新增字段与展示即可。
