## Context

小程序目前是纯前端原型。日历的 2025—2027 年干支数据已预置于本地；1990-01-01 01:00 男命的示例四柱由现有 Go 引擎生成。日历没有个人判断入口，示例命盘也尚未包含供每日干支参考演示使用的扶抑喜忌字段。

## Goals / Non-Goals

**Goals:**

- 从日历所选日期进入独立「每日干支参考」详情页，并在日历提供简短摘要。
- 使用同一份引擎生成的示例命盘喜忌和日历日期标签，让演示文案随日期变化。
- 让无示例命盘、日期超出演示范围、喜忌缺失时有明确状态，不把原型当作真实个人建议。

**Non-Goals:**

- 不实现真实用户登录、出生资料绑定、后端流日接口或数据持久化。
- 不实现传统黄历择日的完整规则，不给出投资买卖指令或结果承诺。
- 不接入 AI。

## Decisions

### 日历保留摘要，解释放在独立页面

日历选中日期卡下增加一张「每日干支参考」卡。未启用时显示「使用示例命盘体验」；启用后显示示例命盘、当日关系和两项提醒，点击打开详情。详情页通过日期参数读取同一份日历数据。相较于把全部说明放进日历下方，这样不会让月历被长文挤下屏幕。

### 示例命盘仍由 Go 引擎生成

扩展示例数据生成器，从 `BaziResult.NatalAssessment.Fuyi` 写入扶抑喜忌和日柱。原型中仅使用这一个固定命盘，不把查询表单输入伪装成绑定结果。启用状态只保存在小程序进程内，重启恢复未启用状态。

### 演示判断只呈现可解释的有限关系

纯函数读取日干五行、日支五行与示例命盘扶抑喜忌，并检查日支是否冲示例命盘日支。输出「偏合／关系复杂／需留意／依据不足」及逐条依据。搬家卡只给行程筹备提醒；财务卡只给计划与风险检查提醒，均不输出「宜搬家」「宜买卖」式结论。此规则只是原型中的展示逻辑，详情页始终标注不等于完整择日或投资判断。

## Risks / Trade-offs

- [静态日历只覆盖 2025—2027 年] → 无日期标签时不进行个人判断，展示范围说明。
- [扶抑喜忌不能代表完整择日] → 把每条依据和未覆盖因素显示出来；事项文案保持为提醒。
- [示例账号与命盘容易被误读为真实绑定] → 使用「示例命盘」「演示判断」标识，启用动作写为「体验」而非「绑定」。

## Migration Plan

仅新增小程序原型文件和页面注册；无需数据库迁移。若正式接入账号与流日接口，以新的结果契约替换演示数据和纯函数，保留入口与页面结构。
