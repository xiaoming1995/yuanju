## Context

当前小程序“我的”页在设置与帮助后直接显示退出登录，没有公众号入口。已有页面视觉整理使用暖白底、轻卡片和少量金色强调；本变更沿用该样式。后端已有 `system_settings` 文本值表、管理员 JWT、受限图片上传目录和 Docker 持久化卷，但没有公众号引导配置。设计稿中的二维码带“示意”字样，不能作为真实配置。

## Goals / Non-Goals

**Goals:**

- 管理员可独立启停、预览和更新公众号引导内容，不需重新发布小程序。
- 小程序在未登录和已登录状态下按同一配置展示轻量入口，点开后提供清晰二维码及可复制的微信号。
- 未配置、关闭、读取失败或图片加载失败时不展示误导性的关注入口。

**Non-Goals:**

- 不使用 `official-account` 关注组件或直接打开公众号资料页的 API；不依赖公众号与小程序同主体。
- 不检测是否关注成功，不发送公众号消息，不新增关注奖励或营销追踪。
- 不承诺长按二维码一定可识别，更不把设计稿二维码投入使用。

## Decisions

### 1. 用单项配置原子保存，引导默认关闭

在 `system_settings` 中用一个专用 key 保存 JSON 配置，字段为 `enabled`、`name`、`wechat_id`、`description` 和 `qr_path`。仓库层封装读取与写入，缺少记录时返回 `enabled=false`；管理员保存时统一校验文本长度、非空字段以及二维码路径属于专用上传目录。单项 JSON 更新避免多个 key 分别保存时出现半成品配置。备选方案是新建专表；当前仅一份全局配置，不需要额外表和迁移。

### 2. 管理接口与公开接口分离

管理员使用现有独立 JWT，读取/保存 `/api/admin/settings/official-account-guide`，上传 `/api/admin/settings/official-account-guide/qr`。小程序通过无需登录的 `GET /api/miniapp/official-account-guide` 读取启用后的展示字段；关闭或配置不完整时仅返回 `enabled=false`。管理员上传返回受限静态路径，不能在保存接口提交任意外部图片 URL。

二维码上传复用现有 `UploadDir` 持久化卷，在 `official-account-qr` 子目录单独挂载静态资源。仅接受有正确文件签名的 PNG/JPEG/WebP，限制体积并使用随机文件名；管理员后台显示上传预览和保存结果。旧图清理须在新配置成功保存后进行，避免更新失败使线上二维码失效。备选方案是让管理员填写外链 URL；这会引入任意图片来源和失效风险，因此不采用。

### 3. 入口独立于账户资料读取

`miniapp/pages/mine/` 在页面显示时独立请求公开配置，不等待 `api.profile()`，使访客也可看到入口。每次读取先清除旧引导数据；接口失败、禁用或二维码加载失败时隐藏卡片，避免上一次的二维码残留。入口位于“设置与帮助”卡片下方、退出登录上方；采用设计稿的低强调卡片，不加入更多福利宣传。

点击“查看二维码”打开页面内的底部展开层，展示真实二维码、名称、说明和“复制微信号”。二维码图片可点击用微信图片预览；可开启图片长按菜单，但界面文案不得写成“长按即可关注”。`wx.setClipboardData` 复制的是可搜索微信号，不是展示名称。加载失败时提供明确关闭动作。备选方案是直接在页面常驻大二维码；这会重新挤压资料和排盘内容，不符合已确认的简洁布局。

### 4. 后台放在系统配置区

新增独立“公众号引导”管理页和请求层条目，包含显示开关、名称、微信号、短文案、二维码上传/预览和保存反馈。启用前要求完整内容；关闭后仍保留管理员已保存的内容，方便重新启用。小程序只使用公开接口，不读取管理员接口或本地硬编码内容。

## Risks / Trade-offs

- [同一手机上的长按识别受微信版本和图片呈现方式影响] → 不把识别作为唯一完成路径；提供复制微信号，并用真实二维码在 iPhone/安卓真机验收。
- [公开静态二维码会被缓存] → 上传使用新随机路径，保存后公开配置指向新路径；小程序重新进入页面时读取最新配置。
- [管理端上传后未保存产生孤立文件] → 保存失败时仍沿用旧配置；实现时处理未引用上传文件和更换后的旧文件清理，不删除当前生效图片。
- [后台文案夸大实际服务] → 限制为短说明，后台预览最终效果；默认文案不承诺奖励、关注成功或消息推送能力。

## Migration Plan

先部署后端读写、上传和静态资源，再部署管理页，最后部署小程序入口。新配置默认关闭；管理员上传真实公众号二维码、填写名称与微信号并在真机核对后再启用。回退小程序页面不会改变已保存配置；关闭开关即可立即隐藏入口。现有上传卷需要继续持久化。

## Open Questions

无需阻塞实现的产品决策：正式公众号名称、可搜索微信号、二维码及引导短文案在上线前由管理员填写；代码不预置设计稿中的示例数据。
