## Context

小程序是原生前端原型：`miniapp/data/calendar.js` 预置 2025—2027 年农历、干支、节气与建除；`buildPersonalDay` 用一份固定示例命盘解释单日干支关系；真实登录、命盘绑定与流日接口尚未接入。当前只能在日历逐日查看，不能按搬家事项查找候选日期。项目已使用的 `lunar-go v1.4.6` 提供每日 `GetDayYi()` / `GetDayJi()`，其中有「入宅」「移徙」标签，但生成器尚未写入这些字段。

## Goals / Non-Goals

**Goals:**

- 从日历进入独立的「找搬家日期」页面，选择有界日期范围，比较候选日期并打开既有单日详情。
- 分开展示通用搬家宜忌、建除与示例命盘关系；每个分组都有可读的入选或未入选原因。
- 无数据、规则冲突或示例命盘未启用时明确显示状态，不编造吉日。

**Non-Goals:**

- 不声称完成传统择日；不评估时辰、房屋方位、家人命盘或实际搬迁条件。
- 不提供投资买卖择日，不接入 AI、真实账户、后端接口或持久化。
- 不改变既有单日 `buildPersonalDay` 的判断含义，也不以建除单项生成事项结论。

## Decisions

### 独立找日期页，复用现有单日详情

在日历选中日期信息附近放「找搬家日期」入口。新页承载事项说明、日期范围、结果分组；点击一日沿用 `/pages/personal-day/index?date=...` 查看详细干支关系。这保留月历浏览空间，也避免出现第二套单日解释。若示例命盘尚未启用，页面先展示「使用示例命盘体验」入口；启用状态复用当前进程级标记，不冒充真实绑定。

### 只保存搬家相关的通用宜忌标签

扩展现有 Go 静态日历生成器，沿用相同日期对象、历法库版本和默认宜忌计算口径，从每日宜、忌列表分别提取「入宅」「移徙」，写入小程序日期记录的两个数组。数组保留命中的原始字词，便于列表解释；空数组表示该日没有相关标签，字段缺失表示数据不完整。不把全部黄历字段打包进原型，也不自行推导宜忌。建除继续来自既有字段，仅展示为补充背景。

### 候选分组不用吉凶分数

纯函数按每个日期的通用标签和 `buildPersonalDay` 结果形成可解释分组：

1. 缺少日期记录或搬家宜忌字段时列入「依据不足」，不凭空推断通用标签。
2. 数据完整时，任一搬家相关标签出现在「忌」中，标为「有通用宜忌冲突」；即使另一标签同时出现在「宜」或个人资料不足，也不得进入优先候选，个人资料不足另行标注。
3. 没有忌且至少一个标签出现在「宜」，才算有通用支持。其中个人关系为「偏合」的列入「优先查看」；其他有效个人状态列入「需要核对」；个人关系为「依据不足」时列入「依据不足」。
4. 没有相关「宜／忌」标签时列入「依据不足」，不以建除值补足。

结果先展示「优先查看」，再展示「需要核对」「有通用宜忌冲突」「依据不足」，组内按日期升序；所有日期可查看，避免用户误认为未出现的日期已被完整判为不宜。每张卡直接列出命中的宜、忌词和个人关系依据，不显示数值排名或「最佳吉日」。

### 日期范围限制与空状态

默认从当天起看 30 个日历日（含当天）；用户可改起止日期，但必须起日不晚于止日、起止合计最多 90 个日历日，且全部落在 2025—2027 年静态数据范围内。若当前日期已超出演示范围，显示范围说明并等待用户选择；没有优先候选时显示明确空状态。日期按本地日历键逐日枚举，不依赖网络或设备时区做干支重算。

## Risks / Trade-offs

- [通用宜忌和个人简化关系可能相互冲突] → 保留两层依据及冲突分组，不合成单一吉凶结论。
- [「入宅」「移徙」并非所有搬家场景的完整描述] → 页面注明标签对应关系，用户可进入单日详情核对；正式版再定义更细的搬迁类型。
- [静态数据及示例命盘容易被当成真实择日] → 所有结果标注「演示数据／示例命盘」，并列出未覆盖的时辰、家人和现实条件。
- [额外宜忌数据增加小程序包体积] → 只预置两个搬家词的命中数组，不导入整套宜忌表到运行时。

## Migration Plan

仅重新生成本地日历数据、注册新页面并增加日历入口；无需数据库迁移。撤回时移除新页面和搬家宜忌字段，原有日历及单日参考仍可运行。

## Open Questions

首版按一份固定示例命盘和「入宅／移徙」两个通用标签验证体验；真实用户绑定、多参与人和时辰规则留待单独变更决定。
