## Context

小程序首页 `pages/home/index` 同时承担任意生辰排盘、最近记录和历史列表；结果页从全局 `activeResult` 直接渲染。本人命盘绑定保存在 `user_personal_charts`，目前只能先建立历史排盘，再手动选择绑定。通用 `/api/bazi/calculate` 与 `/api/bazi/history/:id` 同时供网页端使用，后者只检查记录属于当前账号，不检查是否是本人绑定的记录。

## Goals / Non-Goals

**Goals:**

- 首页直接移除红框整块区域，不增加首页替代模块；今日干支保留。
- 未绑定用户从「我的」配置本人出生资料；详情只展示当前账号已绑定的本人命盘。
- 旧记录不丢失，旧入口和缓存不能绕过详情限制。

**Non-Goals:**

- 改变网页端任意生辰排盘、通用历史或管理员功能。
- 根据出生资料证明用户真实身份，或清理历史数据库记录。
- 改动八字算法与日历计算规则。

## Decisions

### 1. 小程序首页只做减法

移除首页标题/历史快捷入口、查询卡与日期选择弹层，清理只为该表单服务的状态和事件。保留“今日干支”区。下方“最近干支”不再显示任意历史的最新一条：有本人绑定时只显示该盘，无绑定时显示配置引导；这样既保留现有页面结构，也避免把旧的他人排盘作为可点开的详情入口。首页不增加新的本人命盘卡。

### 2. 配置入口归于「我的」

在「我的 → 本人命盘」提供出生日期、整点和性别配置；首次保存创建排盘并绑定，后续修改创建新快照并切换绑定，旧快照保留。「我的」只保留本人命盘卡片，不再重复显示“我的排盘”列表与数量；已有记录仍可从首页历史入口选择本人盘或删除，但小程序不开放未绑定历史记录的详情。选择旧记录时显示可辨认的基本资料并要求确认其为本人资料。

采用后端单次事务完成创建与绑定，避免客户端先调通用排盘、再调绑定接口造成未绑定的残留记录或短暂可访问结果。复用现有排盘计算、`bazi_charts` 和 `user_personal_charts`；若现有保存流程不支持共用事务，应抽取仓储级能力，而非在 handler 写 SQL。

### 3. 本人详情使用独立受保护入口

小程序通过当前登录身份读取本人绑定和对应完整结果，服务端以 `user_id` 查绑定并确认关联盘归属。无绑定返回明确状态；失效会话返回登录错误。结果页只从该受保护响应呈现，不信任 `activeResult` 里旧查询的结果或客户端传入的 `chart_id`。历史与首页本人命盘的点击入口也统一指向这条路径，只有已绑定记录可进入。

网页端既有 `/api/bazi/calculate` 和 `/api/bazi/history/:id` 保持原语义；单靠小程序界面无法阻止持有凭证者直接调用共享通用 API，因此本变更的“不可查询别人”限定为小程序产品入口与本人详情接口。若未来要求整个平台禁止代他人排盘，需要另行改变网页及共享 API 策略。

### 4. 存量记录与状态

旧历史保留在数据库；小程序列表可展示记录摘要供用户选择本人盘、删除旧记录，但未绑定盘不提供详情。退出登录、切换账号、解绑或删除绑定盘时，清除小程序缓存的本人结果并转入配置引导。配置失败时原绑定不变；加载失败显示重试，不将“加载失败”当作“未绑定”。

### 5. 本人命盘卡片的视觉层级

「我的」页本人命盘卡采用接近白色的底与浅边界，保留小面积金色给操作文字。标题区显示“本人命盘”和“查看详情”，下一层展示命盘名称；年、月、日、时四柱以无边框的四列文字呈现，先看标签再看干支。底部以细分隔线区分出生日期和次要的“修改资料”操作。已绑定时整卡可进入详情，修改操作独立拦截点击。加载、未绑定和错误状态沿用同一卡片边界与间距。

## Risks / Trade-offs

- [旧入口或全局缓存绕过限制] → 盘点首页、本人命盘卡片、历史与结果页全部导航路径；结果页必须重新从受保护接口读取。
- [旧用户找不到本人盘] → 「我的」提供已有记录的摘要选择和明确配置入口，不删除旧数据。
- [配置与绑定只完成一半] → 服务端事务提交创建和绑定，失败时回滚。
- [产品限制被理解为全站安全边界] → 在规格和验收中明确小程序范围及共享 API 的现状。

## Migration Plan

先提供后端配置与本人详情接口，再更新小程序入口与结果页。发布后旧绑定继续有效，旧记录仍保留；回滚小程序与接口实现即可恢复原入口，不需要数据迁移。

## Open Questions

无阻塞项。旧历史在小程序保留摘要与删除/选为本人盘操作，禁止未绑定详情；这是对存量数据兼容的默认设计。
