## Context

`stem-level-yongshen-guidance` 已在 `natal_assessment.stem_guidance` 中产出主喜、扶抑可用、调候结构和扶抑忌神的具体天干。结果页首屏仍优先展示 `fuyi.yongshen` 与 `fuyi.jishen` 的五行字符串；例如乙木命盘的“金土火 / 水木”没有传达丙火为共同首取的结论，也迫使用户进入专业区才能看见具体天干。

本变更仅调整结果页总览如何消费已有数据。扶抑仍是五行层的算法结论，而天干列表是对应的展示落点；除“日干调候 + 扶抑”的交集外，不为同一五行中的阴阳两干虚构优先次序。

## Goals / Non-Goals

**Goals:**
- 让首屏总览直接显示具体的主取、可用和慎用天干。
- 用清晰标签区分共同首取与仅有扶抑方向的天干。
- 在缺少新字段或没有共同首取时保持诚实、稳定且兼容的回退显示。
- 保持总览紧凑，并在窄屏自然换行而不影响命盘标题和阅读模式。

**Non-Goals:**
- 不修改扶抑、日干调候、寒热调候、格局、等级、大运或流年算法与评分。
- 不对 `secondary_favorable` 中的天干重新排序或断言其高低。
- 不把 `conditioning_only` 的天干作为后天通用喜神放入首屏。
- 不改变 API 数据结构或移除五行级 `yongshen`、`jishen` 字段。

## Decisions

### 以已有天干指导作为首屏数据源

当 `stem_guidance` 包含内容时，首屏将按其组别渲染，不再同时展示泛化的“扶抑喜用：金土火”“扶抑忌：水木”。具体列表按引擎已有顺序呈现，每个项显示干和五行；共同首取额外显示十神和“日干调候 + 扶抑”来源。

这样首屏与专业区使用同一结论，避免前后口径不一致。直接从五行字符串在前端临时展开为十干被拒绝，因为会绕开后端的冲突排除与中性回退规则。

### 使用三层总览语义，不伪造排序

有 `primary_favorable` 时，显示：

```
首取：丙火 · 伤官        日干调候 + 扶抑
扶抑可用：庚金、辛金、戊土、己土、丁火
扶抑慎用：壬水、甲木、乙木
```

“首取”只对应交集中的第一项；“扶抑可用”与“扶抑慎用”是完整的天干列表，表示同层可用或需谨慎的方向，而非第二、第三优先级。`conditioning_only` 继续只在专业结构区说明原局调候，不进入总览。

当没有共同首取时，首屏不显示“首取”，而显示“扶抑可用”和“扶抑慎用”；若仅有调候结构，也应明确其为“调候参考”，不能包装为扶抑喜用。

### 保留旧响应的五行级回退

旧历史快照可能没有 `stem_guidance`。此时继续显示现有五行级扶抑徽标，保证历史页面和渐进部署不会出现空白结论。新字段存在但所有可展示组为空时，也采用该回退。

### 首屏使用信息行而非等权徽标堆叠

共同首取采用强调色信息行；可用和慎用各为一行紧凑文本，干名使用对应五行颜色。移动端改为纵向排列、允许自然换行，文本不缩小至影响可读性。此方案比将所有干名塞入独立圆角徽标更易扫描，也避免把“慎用”做成过度醒目的告警。

## Risks / Trade-offs

- [较多可用天干会使首屏变长] → 使用三行固定层次和逗号分隔，专业区保留完整理由，不重复十神说明。
- [用户把“扶抑可用”理解为排序] → 标签明确为“可用”而不是“次选”，只给共同交集使用“首取”。
- [旧命盘缺少天干指导] → 回退至原有五行徽标，保持可读结论而非推算新数据。
- [首屏与专业区以后出现不一致] → 两处都直接读取同一个 `stem_guidance` 分组，并加入前端回归测试。

## Migration Plan

1. 部署前端展示调整；新算命盘直接使用已有响应字段。
2. 已保存的旧快照继续通过五行级回退显示。
3. 若需回滚，移除新的摘要渲染分支即可恢复既有五行徽标；后端数据和评分无需迁移。

## Open Questions

无。本变更不引入天干间的进一步强弱排序；如需区分丁火、戊土等的先后，应另立算法变更并定义透干、通根、阴阳和制化规则。
