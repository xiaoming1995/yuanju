## Context

`ResultPage` 已有命盘计算和结果阅读能力，但首屏的 `result-header`、`result-verdict-card` 与 `result-summary-grid` 主要依赖留白和细分隔线组织。星空背景穿透这些区域，顶部身份信息、用神摘要、阅读模式、总评和两个核心摘要面板缺少可辨认的归属边界。

受众包含希望快速获得结论的普通用户和追溯判断依据的专业用户。视觉优化不得改变八字算法、数据返回、阅读模式语义或已有模态框交互。

## Goals / Non-Goals

**Goals:**
- 在不制造卡片堆叠的前提下，为首屏的身份、结论和摘要建立稳定边界。
- 让用户按“我是谁的命盘 → 核心判断 → 本命基础与当前阶段”的顺序阅读。
- 让座驾与路况既有共同的摘要区归属，又能清晰区分为两个独立模块。
- 在桌面和窄屏下保持一致的内容优先级、对齐和可访问性。

**Non-Goals:**
- 不变更四柱、调候、扶抑、座驾等级、大运路况、命格或流年算法。
- 不调整 AI 解读、专业命盘、模态框所承载的数据及交互语义。
- 不引入 UI 组件库、插图、图片资产、新接口或数据库变更。

## Decisions

### 采用三个页面级表面，而非把所有内容包进一个大卡片

首屏重组为相互独立的身份区、结论带和摘要网格。每个页面级表面使用一致的深色半透明背景、弱描边、8px 以下圆角和内边距；它们之间保留明确的垂直间距。座驾和路况作为摘要网格中的两个并列面板，不再仅以中间竖线区分。

把所有信息套入一个大容器会让内部再出现卡片嵌套；继续只用分隔线则会延续模块漂浮的问题，因此两者都不采用。

### 身份区收拢四柱、用神与模式控制

身份区以四柱为唯一视觉核心，出生信息置于其上；天干级用神以三行紧凑信息呈现，命格作为次要标签。阅读模式切换移至身份区的操作侧，在窄屏下自然换行到身份信息之后。身份区不再包含大段结论文字。

这能让“命盘本体”与“对命盘的解释”有清晰分界，且不会增加重复标题。

### 结论带只承担结论，不承担全部证据

“先看结论”改为横向结论带：左侧为标题和简洁结论，右侧为用神摘要或判断依据入口。标签限制为支持该结论的少量关键词。完整的用神细节、等级说明和座驾依据继续通过原有锚点或模态框进入。

将结论塞回身份区会使首屏失去阅读停顿；将所有证据铺在结论带中则会再次造成信息拥挤。

### 摘要区以“本命与当下”为共同语义

座驾和当前路况使用相同标题栏、状态徽标、主体排版和底部操作样式，桌面端按 7:5 左右的比例并列、顶部对齐；窄屏按“命盘座驾 → 当前路况”的顺序单列。每个面板自身承载背景和边框，不再由一个无边界的大网格充当视觉容器。

两面板强制相同高度会在数据量差异大时造成无效留白，因此只保持顶对齐与最小可读高度。

### 将命盘称呼操作放入身份区的辅助工具列

已保存命盘的称呼编辑、保存和发起合盘等操作统一移至身份区下方的辅助工具列。在非登录或无历史记录场景中保持现有条件渲染，不为不可用功能留下空位。

这样工具操作不再位于总览与趋势模块之间，避免打断结果阅读主线。

### 收敛 CSS 令牌，削弱背景对前景的干扰

为页面级表面抽取统一的背景、边框、阴影、圆角和间距变量，替换总览区相互覆盖的局部规则。星空只作为页面底层背景，内容表面通过不透明度更高的背景和细描边保证文字可读；金色仅强调主结论，水蓝色仅标记用神，红色仅标记慎用信息。

## Risks / Trade-offs

- [容器增加导致页面显得卡片化] → 限制为身份区、结论带、两个摘要面板四个一级表面，禁止面板内再套装饰卡片。
- [身份区信息较多导致窄屏拥挤] → 使用单列顺序、可换行的用神行与不压缩文字的工具列。
- [重排工具列影响历史记录功能] → 保留原有条件渲染、表单字段和事件处理，只改变 DOM 位置与样式。
- [CSS 收敛影响专业模式或无座驾数据] → 覆盖简单模式、专业模式、已保存/游客、带/不带座驾和移动端的视觉回归。

## Migration Plan

1. 为总览区建立身份区、结论带、摘要区和工具列的 DOM 边界与语义锚点。
2. 用统一的页面级表面令牌替换现有总览区的透明布局规则，并补齐响应式布局。
3. 回归现有结果数据、阅读模式、模态框和历史命盘工具操作。
4. 如需回滚，仅恢复 `ResultPage` 的结构和样式；不涉及接口、存储或数据迁移。
