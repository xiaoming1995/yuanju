## Context

现有 `calcFuyiStrength` 以少量藏干中的克泄数量做二元判断，未表达透干与藏干的权重差异，也没有把月令、根气、建禄、羊刃作为原局承载力的一部分。原局评估、座驾道路、十神喜忌和历史事件用神还存在不同的强弱路径。

## Goals / Non-Goals

**Goals:**
- 用可复核的同一份原局证据评估扶抑身强弱。
- 把扶抑主用、辅用和忌神用于座驾、大运道路和十神喜忌。
- 使调候优先规则与扶抑结论可同时存在且语义清晰。
- 使旧的命盘快照无须人工迁移即可采用新规则。

**Non-Goals:**
- 不以程序替代人工格局、从格或特殊命局的最终判定。
- 不修改出生四柱、五行统计或历史人物资料。
- 不承诺单一分数可覆盖所有命理流派。

## Decisions

### 建立原局扶抑评估对象

新增内部 `FuyiStrengthAssessment`，由完整 `BaziResult` 生成并输出分数、强弱档、扶抑主用/辅用、忌神和证据。透干按柱位加权；支中本气、中气、余气依次递减；月支权重更高。印、比劫计入助身，官杀、食伤、财计入制、泄、耗。

选择显式对象而非继续扩展旧的布尔函数，因为所有下游消费者都需要同一结论和可说明的依据，且旧函数没有地支位置与结构信息。

### 根气与羊刃作为结构性加权

日主在支有根时增加助身分；临官、帝旺/羊刃额外增加结构分。它们不以神煞文字为唯一依据，而由日干与地支的既定对应表计算，避免展示层数据参与核心推断。

### 扶抑和调候分别保存

`NatalAssessment.Fuyi` 保存全局扶抑的主辅用神；传统调候仍保留在原结果的调候字段。出现调候急时，调用方可优先执行调候策略，但不得把调候元素替换为扶抑用神。丙火极强且燥土泄身时，扶抑以水为主、金为辅。

### 统一下游消费

原局评估、座驾道路、十神喜忌、经典用神和提示词都读取统一扶抑结果。遗留的简化函数仅保留兼容用途，不再驱动新增画像与道路结论。

### 版本化懒回填

将 `NatalAssessmentVersion` 提升一个版本。读取历史快照时，只要版本不匹配即重新计算原局评估、座驾和道路，避免旧的错误结论长期保留。

## Risks / Trade-offs

- [权重属于规则取舍] → 输出得分证据和强弱档，保留单元回归案例，后续可校正权重而不改变 API 结构。
- [特殊格局可能不适用常规扶抑] → 在证据中说明这是常规扶抑判断，特殊格局保留人工复核空间。
- [旧报告文字仍基于旧结论] → 快照数据懒回填；已写入的 AI 文本不自动改写，后续生成会采用新上下文。

## Migration Plan

1. 发布新的评估版本与全局评分器。
2. 保存或读取命盘时触发版本不匹配回填。
3. 以 `乙亥·丙戌·丙子·甲午` 回归，确认日主为极强、扶抑用水金，且道路/十神上下文一致。
4. 如需回滚，恢复旧版本常量即可让旧快照维持旧逻辑；无需数据库迁移。
