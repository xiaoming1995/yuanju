## MODIFIED Requirements

### Requirement: 今日问事请求可独立追溯
系统 SHALL 为已绑定用户的每次今日问事分析保存用户问题、账号、命盘与北京时间日期，并记录最终状态和回答。AI 调用时 SHALL 将请求与共享 Token 用量日志稳定关联，后台从该日志读取实际输入、原始输出和 Token 分类，并保存 Provider、模型、耗时及当时预估成本；未调用 AI 或失败时 SHALL 明确标记缺失字段，不伪造消耗。能从旧 Token 日志可靠解析的问题和上下文 SHALL 出现在同一管理列表，最终用户回答缺失时 SHALL 明确标为历史调用。

#### Scenario: AI 成功回答
- **WHEN** 用户提交有效问题且 AI 输出通过校验
- **THEN** 管理记录包含问题、证据上下文、最终回答、模型和耗时，并通过关联的共享日志展示实际 AI 输入输出及 Token 用量，不重复写入另一份 Token 数字

#### Scenario: 依据不足或 AI 失败
- **WHEN** 服务端没有可用个人依据，或 AI 调用/校验失败
- **THEN** 管理记录仍存在，状态区分依据不足与失败，并保留当次确实产生的输入、输出和用量

#### Scenario: 旧 Token 调用
- **WHEN** 旧今日问事 Token 日志包含可解析的服务端问题上下文
- **THEN** 管理列表展示问题、AI 原始输入输出及用量，并标注最终展示回答无法确认

#### Scenario: 月度用量汇总
- **WHEN** 关联的共享 Token 明细被月度汇总并删除
- **THEN** 问事管理详情仍可读取该次调用的 Token 分类与 AI 输入输出，月度汇总只计算原共享日志一次

### Requirement: 管理员可分页审查请求与详情
系统 SHALL 在独立管理页面和 Admin JWT API 中提供今日问事列表，支持日期、状态与用户筛选及有界分页；列表 SHALL 显示摘要、模型、状态、Token 和估算成本，MUST NOT 批量返回完整 AI 输入输出。详情 SHALL 按需展示请求问题、证据、实际 AI 输入输出与最终回答。普通用户 MUST NOT 访问管理接口。

#### Scenario: 管理员查询和打开单条
- **WHEN** 管理员筛选请求并打开一条记录
- **THEN** 系统返回匹配的分页列表和该条详情，不把其他请求的正文混入结果

#### Scenario: 非管理员访问
- **WHEN** 未持有有效 Admin JWT 的请求访问任一今日问事管理 API
- **THEN** 系统拒绝访问，不返回个人问题或 AI 输入输出

#### Scenario: 历史旧请求
- **WHEN** 管理员查看迁移前的调用日期
- **THEN** 页面仅展示能从旧 Token 日志可靠恢复的问题、输入输出与用量，并明确标注不可恢复的最终结果
