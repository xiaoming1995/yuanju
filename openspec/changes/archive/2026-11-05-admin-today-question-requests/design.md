## Context

今日问事目前只写通用 `ai_requests_log`，有 Token 时再写 `token_usage_logs`；两表没有稳定关联，依据不足时也不调用模型。现有管理员页面分别展示 Provider、通用日志与 Token，无法还原一次问事。请求与输入输出包含个人命盘信息，仅管理员可见。

## Goals / Non-Goals

**Goals:** 每次已进入问事分析的请求有一条可查询的记录；列表轻量分页，单条详情显示问题、命理证据、实际发给 AI 的内容、原始返回、最终展示的回答与逐项 Token；失败也保留状态和诊断。

**Non-Goals:** 不提供用户聊天历史、管理员代问、手工改写结果或跨功能全站日志改造。历史旧请求无法可靠回填问题和证据，不伪造记录。

## Decisions

- 新增 `today_question_requests` 表。请求分析前先插入 `processing`，生成完成后更新为 `success`、`insufficient` 或 `error`。用户删除时级联删除私密正文；命盘删除后保留请求当时的命盘标识快照。相比按时间拼接既有两张日志表，此方式可覆盖没有 Token 的请求且不会错配。
- 记录用户原问题、服务端上下文 JSON、完整 AI 输入（系统与用户部分）、原始 AI 输出、最终回答 JSON、Provider/模型、耗时、Token 分类和当时预估人民币成本。列表仅返回短字段；正文仅在管理员点开详情时读取。对旧请求不回填。
- 服务层返回生成追踪元数据，由 handler 负责创建和完成审计记录；生成失败不向普通用户暴露模型原文或内部错误。原有通用 AI 调用和 Token 日志继续保持。
- 管理员 API 使用既有 Admin JWT 路由，提供有边界的分页、日期/状态/用户筛选与按 ID 详情。前端在既有管理布局中增加入口和页面，按需取详情；长内容可滚动、换行，不作为 HTML 注入。
- 成本复用 `CalcCost`，在请求完成时写入估算值；无模型用量显示 0 和“未产生用量”，不把它误写成免费调用。

## Risks / Trade-offs

- 保存完整命盘上下文和用户问题会增加敏感数据量 → 仅 Admin JWT 可读，不写入列表，随用户删除级联清除，沿用现有后台鉴权。
- 进程中断可能留下 `processing` → 页面明确显示处理中；不将其认作成功。
- Provider 不返回用量时无法估算实际 Token → 记录 0 并标识用量未返回。
- 旧请求缺少可靠关联 → 页面只展示迁移之后的新请求，并说明这一范围。

## Migration Plan

新增顺序迁移 `00034_today_question_requests.sql`；部署后先迁移再运行新后端、前端。回滚删除新表，不影响原有通用日志与 Token 表。开发环境可按现有 Docker 脚本重建前后端验证。
