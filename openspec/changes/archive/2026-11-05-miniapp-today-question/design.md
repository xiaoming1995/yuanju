## Context

小程序首页已按「今日日期与干支 → 通用黄历宜忌 → 本人每日主题 → 方位色彩」分层。`GetPersonalDay` 从当前账号绑定读取本人命盘，`BuildPersonalDay` 计算北京时间所选日干支、通用宜忌和有限的个人事项提示；流年报告已有大运/流年与十二流月资料。现有每日提示并未面向一句具体问题综合大运、流年、流月和流日。首页及相关文件当前有其他未提交改动，实现时须以当时工作树为基础，仅加入约定入口。

## Goals / Non-Goals

**Goals:**
- 保持现有首页结构，只在日期区域后加入「今日问事」卡片，并从本人每日详情提供次入口。
- 对当前已登录且已绑定的本人命盘，仅接受北京时间当天、首版四类事项中的一个具体问题。
- 以可追溯命理资料约束 AI 解读，返回有利程度、支持/冲突依据和现实准备建议；缺少足够相关依据时返回「依据不足」。
- 在账号切换、命盘更换和跨日时避免显示或提交旧状态。

**Non-Goals:**
- 数字成功率、结果保证、未来/过去日期问事、自由聊天和连续追问。
- 把日历择日、通用黄历宜忌或整个每日主题直接等同于某件事的个人结果。
- 新增排盘算法依赖、改写现有每日主题规则，或首版增加问事历史列表。

## Decisions

### 入口与交互

按已确认设计稿，在现有首页日期区域（含可见的每日鼓励语）之后、黄历宜忌之前，使用现有 `today-section`、`today-heading` 与按钮视觉语言加入独立卡片。进入单独问事页面：先选「面试／工作沟通／重要出行／见面社交」，再写一句具体情况；页面显示北京时间当天，不能选日期。本人每日详情可提供次入口，日历任意选中日期的详情不应误导用户可问该选中日。未登录或未绑定时沿用现有登录/本人命盘设置引导，返回后重新校验状态。

### 服务端确定今天与身份

新增受用户 JWT 保护的问事接口，服务端从 `Asia/Shanghai` 时钟取日期，不信任客户端提交的日期、排盘 ID 或干支。读取当前账号唯一本人命盘及其 `LoadOrCalculateResult`；无绑定或关键资料缺失时不调用 AI。请求只接受枚举事项和长度受限的纯文本问题，拒绝空白、越界或不支持的类型。返回中携带服务端日期和命盘 ID，客户端同时核对当前账号/日期/绑定版本；跨过北京时间零点后旧结果标记过期，重新提问才生成新结果。

### 命理上下文与问事答案

复用 `BuildPersonalDay` 获取当日干支、个人每日证据和通用黄历原始标签。大运/流年从当前命盘结果中按**所问日期**选择；立春前后以同一节气口径确定命理年，不能直接以公历年或 `CalcLiuYue` 返回的「今天 index」选择。流月按所问日期所在的节气区间确定，必要时核对日内节气交接；若大运交接时间或某层资料无法可靠确定，则标识该层未知，不补造。所选事项只提取相关的十神、喜忌、冲合及现有事项/主题证据；通用黄历作为单独来源，不升级为本人结论。

服务端将每条证据附稳定 ID、来源层级、日期/干支、方向和解释，构造有界 Prompt，明确用户问题是待分析数据而非指令。AI 输出固定结构：`level`（偏有利／信号交错／需留意／依据不足）、简短结论、引用证据 ID 的支持/冲突依据、2—3 条可执行建议、边界说明。服务端校验枚举、字段长度、证据 ID 与来源，拒绝无依据的确定性预测、数字概率和与事项无关的结论；校验失败可返回受控的依据不足或服务暂不可用，不展示原始 AI 文本。面试参考工作与表达信号，仍不推算录用概率。首版不强制让每个层级都给方向；只显示实有证据及缺口。

### AI、存储与失败

复用现有 active LLM Provider、调用日志和 Prompt 注册/同步机制，为问事建独立 Prompt 模块；不新增 Provider 配置方式。首版不建问事历史表或跨日缓存，每次用户主动提交才调用 AI。问事原文可能进入既有 AI 调用/Token Usage 日志，应遵循现有日志访问与保留策略，避免在错误响应或普通应用日志中打印问题、出生资料和完整 Prompt。模型或结构校验失败时展示可重试状态，不退化成没有依据的回答。财务、医疗等超出四类且可能引出高风险决策的问题不强行归类。

## Risks / Trade-offs

- [大运交接、立春或节气当天的边界误判] → 所有层级按服务端同一日期/节气口径核对，不能可靠确定时在回答中标缺口；用交界日做验证。
- [AI 把传统信号说成录用概率或必然结果] → 固定输出结构、证据 ID 校验、内容边界检查与受控失败。
- [问题语句诱导 AI 忽略依据] → 类型和长度校验、将问题作为数据隔离，并限制回答只能引用服务端证据。
- [首页新增卡片挤压原有内容] → 沿用现有视觉变量与卡片间距，在窄屏和长文案下验证无横向溢出；不改原有模块顺序。
- [每次调用产生费用与等待] → 用户主动提交才调用，前端显示加载/重试，后续按实际使用量决定是否加入额度或缓存。

## Migration Plan

先注册并同步新的问事 Prompt，再上线受保护接口，最后展示小程序入口。新接口/页面是增量功能，旧客户端保持可用；回滚小程序入口和接口即可停止新调用，不影响已有每日结果。首版无需新增业务表；若现有 Prompt 同步机制需要迁移，按仓库既有迁移方式添加并验证。

## Open Questions

- 首版是否需要次数额度或结果历史，待真实使用数据再决定；当前不纳入范围。
