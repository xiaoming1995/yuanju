## Context

后台已有独立的 `--admin-*` 变量和 `AdminLayout`，但这些变量目前定义为深色；用户端仍使用另一套深色主题。后台各页面大多复用变量，少量按钮文字和浮层阴影直接写死颜色。设计稿已确定为「清爽侧栏」布局、暖白页面、白色卡片和雾蓝强调色。

## Goals / Non-Goals

**Goals:** 统一后台及登录页的浅色视觉层级；使侧栏导航易浏览；保证表格、表单、按钮、状态和窄屏可读。

**Non-Goals:** 不修改用户端主题、后台 API、数据逻辑或引入组件库。

## Decisions

- 以现有 `--admin-*` 变量为基础集中调整色板，保持页面现有样式可继承；用户端 `--bg-*` / `--primary` 不变。相较于逐页覆盖颜色，可减少不一致。
- 保留左侧栏路由结构，按工作台、内容与 AI、系统配置分组，并允许菜单区独立滚动；窄屏将其收为可展开导航，避免固定宽度挤占内容。
- 公共卡片、按钮、输入、表格使用轻边框、白色表面与克制阴影；危险操作保留独立红色语义。
- 定向修正各页写死的深色适配样式；宽表格由容器水平滚动，避免整页溢出。

## Risks / Trade-offs

- [部分页面直接写死颜色] → 检索后台文件并针对性调整，再做页面抽查。
- [浅色背景降低弱文本可读性] → 提高辅助文字与状态色对比度，检查按钮和输入焦点。
- [侧栏条目较多] → 导航区域滚动，保持品牌和账户区域可见。

## Migration Plan

纯前端样式与布局更新；可通过回退本次提交恢复旧样式。

## Open Questions

无；采用已确认的雾蓝「清爽侧栏」设计稿。
