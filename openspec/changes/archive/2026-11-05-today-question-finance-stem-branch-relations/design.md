## Context

今日问事已有财务事项分类、命盘扶抑/十神方向证据和 AI 证据 ID 校验。六冲、六合、天干五合规则已经保存在八字算法层，问事尚未复用。AI 的方向标签以服务端证据为准；有支持和留意两类时必须同时说明。

## Goals / Non-Goals

**Goals:** 针对财务事项核对本人日柱与大运、流年、流月、流日的冲合；把规则、双方干支、层级和适用边界写入证据；在回答中说明宜做的准备及忌做的仓促决定。

**Non-Goals:** 用冲合计算收益率、推荐证券或下达买卖/仓位指令；把单一“合”断为获利，或把单一“冲”断为亏损。

## Decisions

- 八字包提供复用现有关系表的只读判断函数。问事使用这些函数，不在服务层复制规则表。只比较本人日干/日支与已确认的运势层级；交界日缺失的层级不比较。
- 地支六冲记为 `review`，解释为宜复核投资计划、流动性与风险。天干五合和地支六合只有在该层对应干/支五行的本人扶抑方向明确时才沿用 `candidate` 或 `review`；中性关系不作为有利或不利的证明。合只表示关系存在，不推断合化成功。
- 关系证据作为财务事项的附加本人依据，仍经证据 ID 校验；系统指令要求财务 summary 明确写出“宜做的准备／忌做的仓促行为”，并解释冲合只是文化参考。现有结果结构与小程序展示复用，无需新增表或前端控件。

## Risks / Trade-offs

- [把冲合误当市场预测] → 证据文案和系统指令限定到投资研究、预算和风险复核，保持买卖类输入拒绝。
- [合冲并存时误给单一结果] → 现有双向引用校验要求 `信号交错`，不抹去冲突。
- [节气交界产生伪精确关系] → 沿用现有层级缺失处理，未确认的流月/流年/大运不生成关系证据。

## Migration Plan

无数据迁移。发布后新问事请求使用新的证据生成规则，既有日志及回答保持原状；回滚服务代码即可恢复旧规则。
