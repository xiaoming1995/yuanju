## Context

当前服务端从问题关键词推断事项范围，构造可引用证据后，只要没有定向证据便直接返回固定的「依据不足」。这使任何规则遗漏都绕过 AI，输出没有针对问题的准备建议、AI 输入输出或 Token 记录。前端已经能展示「依据不足」和建议，无需改入口。

## Goals / Non-Goals

**Goals:** 所有通过校验且绑定本人命盘的今日问事均经过 AI；无定向依据时仍给针对问题的现实建议，同时防止 AI 补造命理依据或预测结果。

**Non-Goals:** 自动扩大命理规则覆盖、让 AI 自行计算干支、提供数字成功率、无命盘用户提问、改变次数计费规则。

## Decisions

- 移除「无定向证据直接返回模板」的服务端短路。`BuildTodayQuestionContext` 保留可核对的命盘、层级、通用日期和未知项，随后统一构造 Prompt 和调用 Provider。
- 在每次调用的系统指令中强制：若没有可引用的定向个人证据，只能返回 `依据不足`、空依据 ID 与 2—4 条贴合问题的现实建议。该指令独立于后台可编辑 Prompt，保证旧维护版 Prompt 也遵循此边界。
- 更新出厂 Prompt 说明无证据时的输出要求；后台已存在的维护版 Prompt 不自动覆盖。现有服务端 JSON 校验继续拒绝不存在的证据 ID、无证据的有利判断和成功保证。
- AI 失败或输出校验失败保持 `error` 状态并退回免费或额外次数；只有通过校验的 `依据不足` 回答计次。Token 及 AI 输入输出继续走共享日志。

## Risks / Trade-offs

- 无证据问题也会消耗模型 Token → 保留每日次数限制、管理员调用日志和 Token 统计。
- 模型可能不按无证据约束输出 → 服务端校验拦截并作为技术失败退回次数。
- 旧维护版 Prompt 未自动更新 → 运行时系统指令持续施加核心约束，出厂 Prompt 可供管理员手动采用。

## Migration Plan

无需数据库迁移。更新后端镜像；用模拟 Provider 验证空证据请求确实发起调用、返回建议、记录 Token，以及失败退回次数。回滚后恢复旧的短路行为。
