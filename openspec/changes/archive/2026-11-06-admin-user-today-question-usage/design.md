## Context

`/api/admin/users` 目前只返回用户及查盘等统计；今日问事的免费额度由 `system_settings.today_question_daily_limit` 控制，额外余额来自 `today_question_credit_entries`，逐次状态在 `today_question_requests`。个人额外次数可跨日使用，不能把「已用 / 免费上限」误当总额度。

## Goals / Non-Goals

**Goals:** 管理员在用户列表直接核对北京时间当天的有效使用、剩余及免费/额外来源；显示与实际预占和失败退回逻辑一致。

**Non-Goals:** 更改额度规则、增加每日个人覆盖配置、展示历史用量曲线、新增统计表或支付功能。

## Decisions

- 扩充现有用户列表行响应为嵌套 `today_question` 摘要：北京时间日期、每日免费上限、今日有效已用、其中免费已用、处理中、其中免费处理中、额外余额及当前剩余。`已用`仅数已计费的 `success` / `insufficient`；处理中单列，失败及旧未计费记录不数。
- `剩余 = max(0, 免费上限 - 免费已用 - 免费处理中) + 额外余额`。额外处理中已在预占时从余额扣除，不再重复减。管理员调高全局免费上限后列表随刷新立即变化。
- 列表先分页，再只针对当前页用户批量汇总问事记录和流水。若当前页存在超过十分钟的处理中记录，按既有用户级锁与退回逻辑先回收，再以单条聚合 SQL 获取同一快照；无需逐用户请求余额详情。
- 用户列表在“累计查盘”后增加一列「今日问事」，主行显示已用与剩余，次行显示免费已用/上限及额外余额；有处理中时另显数量。现有“增加次数”按钮保留在操作列。

## Risks / Trade-offs

- 统计与问事提交可同时发生 → 列表是一刻的快照，刷新可获取最新值；单次聚合避免拆分查询得到相互矛盾的数字。
- 超时请求长期占用额度 → 列表复用已存在的超时回收，保持与用户下次提问时的额度一致。
- 额外次数曾被消费而每日免费次数次日重置 → 明确拆分免费与额外，避免 `已用` 大于每日免费上限造成误解。

## Migration Plan

无数据库迁移。部署后端与前端后核对免费、额外、处理中、失败退回及跨日显示。回滚只撤销列表新字段与 UI，不修改问事额度数据。
