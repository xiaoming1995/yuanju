## Why

微信小程序目前只有固定示例和进程内登录、历史状态；网页用户依赖邮箱密码与同一 `users.id` 下的命盘数据。正式接入必须提供微信身份入口，并保持现有网页账号、认证接口和历史数据可用。

## What Changes

- 为普通用户增加微信小程序身份登录与已登录网页账号绑定，复用 `users.id`、普通用户 JWT 和现有业务数据。
- 允许微信创建的普通用户没有邮箱或密码；网页邮箱注册、登录以及管理员创建邮箱用户继续按现有协议工作。
- 将网页邮箱公开注册开关与小程序首次登录建号开关分离；后台用户列表和个人中心可展示无邮箱用户。
- 关闭公开管理员注册，提供受控的首次管理员初始化方式。
- 小程序首页、结果页、历史、我的接入真实排盘、用户与历史接口；保留日历和个人择日的演示边界，不把固定示例作为真人结论。

## Capabilities

### New Capabilities

- `dual-channel-user-auth`: 网页邮箱用户与小程序微信用户的统一身份、登录、绑定、禁用和兼容行为。
- `miniapp-backend-integration`: 小程序真实排盘、历史和个人中心的请求与状态契约。

### Modified Capabilities

- `admin-user-registration-control`: 公开注册开关仅控制网页邮箱注册，小程序首次建号独立控制；管理员首次初始化不得通过公开注册接口完成。

## Impact

- 后端用户模型、认证服务、路由、用户查询、迁移、管理员入口及测试。
- 小程序请求层、首页/结果/历史/我的页面及测试。
- 网页端用户和管理员页面的无邮箱展示；现有邮箱登录请求格式保持兼容。
- 需要真实微信 AppID/AppSecret 与可访问的 HTTPS API 域名完成最终真机联调。
