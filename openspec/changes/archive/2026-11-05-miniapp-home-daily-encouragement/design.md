## Context

首页已并行读取真实通用日期和当前账号绑定命盘的 `/user/personal-day`，并用请求序号、令牌及北京时间日期防止旧结果覆盖。个人结果已有 `status`、`label`、`summary`、`evidence`，但没有完整四柱对每日干支的总运算法。设计稿把一句文案置于日期三柱与黄历宜忌卡之间，现有模块顺序不变。

## Goals / Non-Goals

**Goals:** 从现有个人关系状态生成一句可追溯、轻快但保守的首页鼓励语；点击后进入同日完整依据；确保无绑定、缺失依据及异步切换时不展示过期个人内容。

**Non-Goals:** 不新增「好运／平运／差运」评分、不扩展四柱冲合算法、不让通用宜忌决定个人语句、不改变页面其他内容或新增用户设置。

## Decisions

### 1. 纯展示映射

在小程序 `utils` 中用纯函数把 `status` 和方向映射为文案。`supportive` 使用积极但有限的「主动迈一步」；`caution` 使用「先稳一稳」；`mixed`、未命中明确喜忌的 `undetermined` 使用平稳语气；`undetermined` 中单边忌神使用谨慎语气。`insufficient`、未知状态、缺少日期或依据时不生成文案。文案不含确定事件、财务买卖或安全保证。同一状态稳定输出同一句话，避免刷新时随机跳变。

### 2. 称呼和位置

仅用已绑定命盘的 `gender` 选择「靓仔／靓女」，无法识别时用「朋友」；性别不参与状态映射。显示为三柱下方的一条浅绿提示，不增加页面标题、独立大卡或模块重排。文案可以换行，窄屏不截断。入口复用首页现有 `openTodayDetail`，因此与底部详情入口一致。

### 3. 生命周期

刷新日期、切换账号或退出登录时和 `personalDay` 一起清空提示。只在当前绑定命盘与同日个人响应均有效时设置。当前 `loadTodayPersonal` 已有请求序号、令牌及日期检查，沿用该检查后再更新视图。

## Risks / Trade-offs

- [单句被误读为完整运势结论] → 只描述「今天节奏」和有限行动，入口直达原有依据；不显示好运分数或差运断言。
- [命盘性别不等于用户偏好的称呼] → 该版按用户提出的例句使用绑定命盘字段，未知值用中性称呼；自定义称呼留给独立需求。
- [示意稿文案与真实结果不一致] → UI 不写死示意日期、干支或主题，用真实个人结果驱动。

## Migration Plan

仅小程序代码变更，无数据库迁移；回退时移除提示区与映射，原有首页及 API 不受影响。
