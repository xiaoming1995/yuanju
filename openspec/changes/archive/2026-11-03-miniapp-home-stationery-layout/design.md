## Context

首页现有 `index.wxml` 在一张 `today-card` 中顺序展示日期三柱、完整通用宜忌、本人事项、当日干支关系、方位色彩及详情入口；`index.js` 已分别读取同日服务端通用和个人数据，并处理跨日、账号切换及状态。用户选择的方案 C 是暖白纸张式三卡布局，设计图里的个人文案仅为示例。项目原生微信小程序使用 WXML/WXSS 和全局 `app.wxss`；首页应优先局部改动。

## Goals / Non-Goals

**Goals:** 用方案 C 的日期抬头、细金线和轻微纸层次建立清楚的三段信息层级；所有真实数据与状态仍完整可达；窄屏和长宜忌列表可读。

**Non-Goals:** 修改后端数据或判断逻辑、引入 AI 日运、将设计图的个人结论硬编码、重做日历和我的页面、增加依赖。

## Decisions

### 1. 三卡结构和数据分层

日期及三柱位于卡片上方；第一卡仅放通用黄历宜忌，第二卡放本人事项、来源、当日干支关系及方向关系，第三卡放方位色彩及其依据。页面底部保留一个同日“查看今日完整依据”入口。与单张长卡相比，三卡更贴近选定方案，也能让通用信息与个人结果自然分开。全部有效事项和完整宜忌仍渲染，不按设计稿固定为三条或两列各四项。

### 2. 视觉语言以可实现性为界

首页局部 WXSS 使用暖白背景、双层浅金边、标题细线和纸张错层阴影；两张本地透明图片分别承担页首梅枝与页尾远山，避免把设计图中带示例文字的整张图当页面背景。个人卡使用小金色圆钉点缀。绿色对应宜、红色对应忌，个人级别继续沿用现有状态色。微信原生顶部胶囊与 Tab 栏仍保留，首页内容在系统导航栏下方显示；首页页面标题由内容区字标呈现。

### 3. 保持动态内容与异常状态

保留 `calendarPreview`、`calendarDay`、`personalGuidance`、`personalDay`、`personalState` 的读取与同日校验，不加入独立的新数据源。日期抬头显示现有真实农历文本，不采用生成图中未经核实的农历日期。未登录／未绑定显示配置入口；通用请求失败、个人请求失败、无有效事项、无明确方位都保持清晰文案。方位卡只显示服务端 `luck.available` 的结果和 `reason`。

### 4. 窄屏适配

宜忌两个区域可并排，窄屏时纵向排列；标签按文字自然换行，不设固定高度。本人事项按数量顺序排列，来源和摘要允许折行。触控入口保持足够高度，不让底部 Tab 栏遮挡免责声明或详情入口。

## Risks / Trade-offs

- [三张卡增加页面长度] → 使用紧凑卡内间距，同时保持完整条目，不截断业务信息。
- [纸张装饰与动态长文本相撞] → 装饰只放在边缘或标题附近，不覆盖正文。
- [示例设计图被误作真实结论] → 只使用接口数据，并保留通用／本人标签及不可用状态。
- [局部样式影响历史态] → 新选择器限定首页每日参考区域，检查历史列表和弹层。

## Migration Plan

仅发布小程序首页模板与样式，无数据迁移。视觉不合适时可回退相关首页文件，原接口与导航不受影响。

## Open Questions

无阻塞项；以用户已选的方案 C 为视觉方向，实机检查后微调装饰密度和间距。
