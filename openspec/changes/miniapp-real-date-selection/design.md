## Context

`miniapp/pages/moving-date/` 目前同步读取 2025—2027 年的 `data/calendar.js`，用 `data/demo.js` 的固定干支和 `buildPersonalDay` 形成四组结果。页面把示例关系作为“优先查看”条件，并要求用户先启用示例。后端已有无需登录的 `GET /api/calendar/day` 和需登录、需绑定的 `GET /api/user/personal-day`，二者均由 `lunar-go` 计算，支持 1900—2100 年。前者一次只返回一天；后者的事项规则没有覆盖搬家、结婚、开业、动土。相关文件已有未提交改动，实施前须核对差异。

## Goals / Non-Goals

**Goals:** 五事项在服务端支持日期内按真实通用宜忌筛选；不再依赖示例开关、固定干支或本地年份；结果和详情说明来源，未绑定也能用；最多 90 天的加载与错误状态可靠。

**Non-Goals:** 给五事项增加专属个人命理规则、时辰/方位/参与人合择、投资买卖时机、日历或每日参考页的整体去演示化、数据库迁移。

## Decisions

### 1. 用有界批量日历接口提供筛选资料

新增无需登录的日期范围读取接口，接收 `start`、`end`，按中国民用日期校验真实日期、顺序、1900—2100 年和含两端最多 90 天。复用现有服务端历法计算口径，返回日期升序的 `date`、农历、日干支、完整 `yi`/`ji` 数组；若保留建除展示，则由同一服务端结果提供建除，否则从择日页去掉建除字段，不能回落到本地示例。接口一次返回完整范围，任何日期失败时返回整体错误，不允许客户端展示部分“候选”。

相对于逐日调用现有接口，这避免 90 次请求及部分成功导致的误读。范围上限限制服务端工作量；不增加依赖和数据库查询。具体路径和公共日期 DTO 由实施时沿用当前路由命名确定。

### 2. 客户端只按所选事项的原始标签分组

保留既有五项映射：搬家→入宅/移徙，结婚→嫁娶，开业→开市，出行→出行，动土→动土；`诸事不宜` 视作通用忌。服务端返回完整原始宜忌，客户端筛出相关标签并给出原因。相关忌优先列入“有相关忌”；无相关忌且有相关宜列入“有相关宜”；均无则为“未列相关标签”。宜、忌同时命中必须展示两侧标签，不进入正向候选。缺失字段或返回日期不全作为资料错误，不用缺失值补正向判断。组内按日期升序，不使用个人整日状态打分或排序。

现有 `ACTIVITIES` 和日期范围校验可改为复用的纯逻辑；删除示例干支参与分组的分支。建议把“优先查看”改为“有相关宜”，避免暗示已完成个人或完整传统择日。

### 3. 详情与本人参考分开

在择日页展开日期详情，显示该日完整通用宜忌、事项命中标签、分组原因及来源，使未登录用户可核对列表。已绑定用户另有“查看本人每日参考”入口，沿用既有 `personal-day` 接口和页面；不得把其整日关系回填成搬家、结婚、开业或动土的个人结论。已支持的旅行提示也保持其原有“通用日历/本人命盘”来源，不改成五事项统一排序。列表选中的事项与日期在返回后保留。

选择页内展开而非直接跳现有每日详情，是因为该详情对未绑定用户会进入固定示例分支，并且真实分支尚未显示所选事项的筛选依据。

### 4. 数据状态和文案

首次进入按北京时间的今天建立默认 30 日范围，超出服务端支持范围时显示明确错误；用户改范围或事项时清掉旧结论，使用请求序号丢弃过期响应。页面移除“前端演示”“演示数据”“原型说明”和启用示例按钮，改为简短的“通用宜忌参考”说明及事项映射。网络失败、资料不完整、无相关宜各有独立状态和重试路径。保留对时辰、参与人和现实安排的必要边界说明，但不再称该页为演示。

## Risks / Trade-offs

- [传统标签与现代事项不完全等同] → 显示每项采用的原始标签和命中词，不把“开市”扩展为交易或投资结论。
- [90 天批量计算或响应过大] → 严格限制跨度；只返回列表所需字段，前端分批显示卡片并测量实际耗时。
- [异步返回覆盖新筛选] → 用请求序号、范围和事项核对响应；失败时清除旧结果。
- [现有示例详情混入真实列表] → 通用日期详情在择日页内完成；本人每日入口仅在绑定状态明确时出现。
- [现有未提交修改被覆盖] → 实施前逐文件检查当前差异，最小范围改动。

## Migration Plan

先增加批量只读接口及测试，再切换择日页和详情入口，最后删除该页的演示文案与无用样式/状态。无需数据迁移。回退时恢复旧页面和路由，不影响已有单日接口。

## Open Questions

无阻塞项。建除若无法由同一实时日期源提供，就从择日结果卡移除；完整建除可继续在独立日期资料功能中展示。
