## Context

小程序已有搬家日期范围筛选：静态日历只保存「入宅」「移徙」命中标签，固定示例命盘提供通用单日干支关系。页面和日历入口均写死为搬家。`lunar-go v1.4.6` 的每日宜忌包含「嫁娶」「开市」「出行」「动土」等原始标签，可沿用同一数据来源。

## Goals / Non-Goals

**Goals:** 一页切换五种事项；每次切换都按该事项重算候选分组，显示命中的原始宜忌和示例命盘关系；入口名称与页面功能一致。

**Non-Goals:** 不实现时辰、方位、多人命盘或事项专属命理规则；不把开市扩展为交易、求财或投资建议；不接入后端。

## Decisions

1. 保持现有独立页面路径与日期范围控件，新增单选事项区。默认搬家，切换后保留起止日期、重算结果；返回单日详情也保留所选事项和范围。日历顶部与卡片入口均改为通用「择日」。这样可以复用已验证的导航，避免更换页面路径导致开发者工具热更新失效。
2. 活动配置集中定义：搬家→入宅／移徙，结婚→嫁娶，开业→开市，出行→出行，动土→动土。页面显示映射，尤其注明「开业」在此仅按「开市」原始标签演示；不把订婚、修造、交易等相邻事项自动并入。
3. 静态日历改存上述六个原始事项标签在宜、忌中的命中数组，另保留「诸事不宜」原始忌标签。每个日期都生成两个数组；缺字段视为资料不完整。筛选时只取所选事项的标签，其他事项标签不影响该事项的分组。
4. 复用搬家页四组规则：相关忌（含诸事不宜）优先标冲突；没有相关宜和忌则依据不足；有相关宜且无相关忌时，示例个人关系偏合为「优先查看」，其他有效状态为「需要核对」，个人依据缺失则「依据不足」。建除只展示，不能补出候选。从结果卡进入单日详情时传入事项，详情显示同一事项的原始宜忌与分组原因，并继续说明个人关系只是通用干支参考；隐藏原先仅针对搬家／财务的提醒，避免跨事项误读。

## Risks / Trade-offs

- [现代事项与传统标签并非完全等同] → 每个选择项显示原始标签映射，避免隐藏推断。
- [固定命盘关系被误认为完整择日] → 继续标注演示，展示通用标签和个人关系两层依据，不给最佳吉日或分数。
- [数据包增长] → 只保存六个事项标签与「诸事不宜」，不打包完整宜忌表。

## Migration Plan

重新生成 2025—2027 年本地日历，改造原有页面和日历入口；无需持久化迁移。回退时恢复旧页面与旧静态数据生成器。

## Open Questions

本轮五项和原始标签映射已确定。正式版如何绑定真实命盘以及是否增加事项专属规则，留待单独设计。
