## Decisions

### Treat `寅` as a distinct early-spring thermal condition

`寅` SHALL map to the user-facing condition `初春偏寒` and require `火`. It will use the existing seasonal evidence states (`seasonal_resolved`, `seasonal_partial`, `seasonal_unresolved`) rather than a new urgency taxonomy. This keeps the behavior compatible with existing thermal display while making the requirement visible and testable.

The alternative, folding `寅` into winter, would overstate the season; continuing to treat it as neutral loses the requested fire requirement.

### Add a separate month-command strength contribution

The 扶抑 evaluator SHALL add a named month-command contribution before classifying the total strength. A day master whose element equals the month-command element receives a positive `得令` contribution; a day master generated by the month command receives a smaller positive contribution. Draining, controlling, and being-controlled month-command relations receive the corresponding directional contribution. The exact amount is centralized with the existing score constants and recorded as evidence, not hidden inside a pillar subtotal.

This preserves the current pillar and hidden-stem evidence while representing the independent seasonal fact that the month command is the primary strength reference. Replacing all existing evidence with a month-command-only model was rejected because it would discard useful whole-chart information.

### Derive shared-priority yongshen after each layer is assessed

After thermal and 扶抑 results are calculated, the natal assessment SHALL compute an alignment object. An element is a shared-priority yongshen only when it is both a thermal required element and one of the 扶抑 yongshen elements. Day-stem regulation support may be included as explanatory evidence, but it is not required to establish the two-layer alignment.

The alignment retains its sources, elements, and human-readable explanation. It does not replace `thermal.required_elements`, `day_stem.required_stems`, or `fuyi.yongshen`; the full 扶抑 list remains available for cases such as `金土火`.

Using a single merged yongshen field was rejected because it would obscure whether an element arose from seasonal thermal need or strength balancing.

### Alignment is explanatory, not an extra score

The current thermal and 扶抑 assessments continue to contribute their own scores. The shared-priority yongshen SHALL not produce an additional grade increment, cap change, or duplicate evidence delta. Vehicle profile text, API consumers, and AI prompts present it as a prioritization cue: `共同优先用神：火（寒热调候 + 扶抑）`.

Adding a third score would double-count the same source facts and artificially inflate grades.

### Version recalculated natal results

The natal assessment algorithm version SHALL be incremented. Cached assessment, vehicle, and report data tied to the old version must be recalculated through the existing version mismatch path.

## Risks / Trade-offs

- [Month-command scoring changes more than the target chart] → Cover same-element, generated, drained, controlled, and neutral cases with focused unit tests and retain existing global evidence in the detail output.
- [A user mistakes shared priority for the only yongshen] → Display it as `共同优先用神` alongside, rather than in place of, complete thermal and 扶抑 results.
- [Thermal label is interpreted as a severe winter condition] → Use the specific label `初春偏寒` and existing non-severe seasonal evidence states.
- [Cached historical result differs from recalculated result] → Version the natal assessment and use existing recalculation behavior instead of silently mixing versions.
