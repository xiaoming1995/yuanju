## Context

座驾分级当前将“取到格名”视为结构加分，调候和扶抑又各自采用不同的取用口径；大运道路则继续读取旧的 `yongshen/jishen`。这使基础盘等级没有反映格局的成败，也无法解释一段大运究竟在补扶抑、助格还是破格。

已有计算引擎已提供四柱、藏干、十神、根气、五行、神煞、格名和大运数据。本设计只在这些确定性输入上建立新的版本化评估层，不新增外部依赖，也不改写既有 `yongshen/jishen` 的兼容语义。

## Goals / Non-Goals

**Goals:**
- 以“调候急需优先；非急时扶抑为基线；格局、制化、流通拉开等级”为固定判断顺序。
- 为每个等级和大运道路给出规则、输入和影响方向，供前端与 AI 使用。
- 对已保存快照惰性补全，避免旧记录继续使用旧版座驾算法。
- 保留既有 API 字段和页面可读性。

**Non-Goals:**
- 不将所有古法格局、从格、化气格或流派争议规则一次性自动化。
- 不用名人案例、神煞或单一格名直接判定人生高低。
- 不更改旧 `yongshen/jishen` 的输出含义，也不重写 AI 报告全文。

## Decisions

### 1. 新增版本化 `NatalAssessment`，作为座驾和道路的唯一判断上下文

评估输出包括：调候状态、扶抑用神及其支持度、格局质量与制化证据、原局流通及支干关系、承载状态、风险、总分和等级。每条证据带来源、规则标识、影响值和说明。

选择独立字段而非复用旧 `yongshen/jishen`：旧字段仍服务已有页面和兼容流程，且包含调候字典命中语义；新评估明确标识调候急需和扶抑结论，避免语义混用。

### 2. 采用硬门槛与结构评分的组合，而非“有格即加分”

- 仅极寒、极热等明确急需进入调候硬门槛：未解限制等级，已见透干或藏支按可用程度评分；没有急需时调候为中性背景。
- 扶抑按日主强弱、喜用与忌神的透藏支持作为基础承载。
- 格局质量由格神透出、通根、成格组合和破格组合决定。首期覆盖正官、七杀、食神、伤官、财、印、建禄/月禄、月刃和杂气等已存在格名；例如伤官配印/生财、食神制杀、杀印相生、官印相生、财官/食伤生财为有效制化，伤官见官、枭神夺食、财多身弱、比劫夺财等为风险。
- 原局五行的连续相生链和三合/三会、六合、冲刑害仅作为关系和流通修正；它们必须结合扶抑喜忌解释，不能一律视为吉或凶。

替代方案是继续给“非杂气格”固定加分；它不能区分格成、格破和无制，因此不采用。

### 3. 用同一评估驱动大运道路

大运五行优先读取新评估的调候急需和扶抑用神，而非旧字段。道路额外匹配大运天干、地支十神与原局“助格十神/破格十神”，生成“格局作用”证据。金不换、十二长生、神煞等保留为次级路况修正。

首期只说明“助格、补短、加重风险”等可验证作用，不在单一大运上断言人生结果或宣称必然“成格”。

### 4. 版本化惰性回填

计算新盘时立即写入 `natal_assessment`。读取历史快照时，若字段缺失或版本落后，基于快照四柱补算评估，再同步重建座驾和道路并保存。此方式不需要数据库结构迁移，且旧 JSON 快照保持可读。

## Risks / Trade-offs

- [格局规则存在流派差异] → 首期只使用项目已有格名与清晰的常见制化关系，证据显示规则名称，后续可扩展而不暗改结论。
- [权重造成等级波动] → 以硬门槛限制明显急需和扶抑无力，增加覆盖成格/破格的单测，保留版本号以支持未来重算。
- [旧快照缺少藏干或十神] → 回填按可得数据保守判断，无法确认时标为“待定/部分成立”，不虚构加分。
- [道路说明过度归因] → 只描述结构方向与可见输入，不输出具体事件或成功承诺。

## Migration Plan

1. 发布新评估结构和计算逻辑，同时保留原有字段。
2. 新排盘直接保存新版结构；读取旧快照时惰性补全并重存。
3. 前端在旧字段缺失时继续兼容显示，在新版存在时展示新的证据来源。
4. 若需回滚，前端可忽略新字段，后端可继续读取已保存快照中的旧座驾字段；不删除任何历史数据。

## Open Questions

- 首期格局覆盖以现有 `DetectMingGe` 的格名为边界；从格、化气格等复杂格局将在有明确规则和样本后单独提案。
