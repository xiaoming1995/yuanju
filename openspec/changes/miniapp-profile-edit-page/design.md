## Context

“我的”页同时承担资料展示与编辑，表单展开后挤占命盘和工具区域。现有资料接口、微信头像选择、昵称审核回调及跨页反馈均可复用。

## Goals / Non-Goals

**Goals:** 将编辑集中到独立页面，按项自动保存，返回后刷新；首次注册生成可修改的默认昵称；失败保留草稿。

**Non-Goals:** 修改身份认证、数据库结构或微信头像昵称的获取方式。

## Decisions

- 注册普通页面 `pages/profile/index`，使用原生导航栏标题“个人资料”。“我的”顶部资料区通过现有 navigation feedback 打开该页，移除内联表单及编辑状态，避免两处维护同一表单。
- 新页自行读取已登录用户资料，展示头像与昵称，复用 API 模块保存。页面加载失败显示重试；登录失效提供返回登录入口，避免误编辑缓存资料。
- 首次注册与普通编辑统一采用分项自动保存。头像回调后直接上传；昵称失焦、微信审核通过后更新。两项独立提交，阻止同一字段重复提交。
- 保存成功留在当前页，显示字段状态；原生返回后由“我的”页 onShow 重新读取资料。失败保留草稿并提供分项重试；未保存内容使用平台支持的离页提示。
- 保留浅灰底、白色卡片和金色主色，将头像和昵称排为紧凑两行，移除重复标题、保存及取消按钮。
- 后端创建微信账号时用标准库 crypto/rand 生成六位随机数字，以“缘友”作为前缀，与身份绑定在同一事务中持久化。昵称仅作展示，不作为唯一身份；不更新已有账号昵称。

## Risks / Trade-offs

- 两个资料字段分别提交，可能一项成功、一项失败 → 状态与重试入口分别归属各字段。
- 微信昵称审核异步返回 → 等待 nicknamereview 通过，同一字段审核或保存时禁止再次编辑；失败保留输入并允许重试。
- 3.17.5 模拟器用错误文本精确匹配设置 timeout，带前缀的超时可能返回 pass=false、timeout=false；组件还会清空输入 → 未通过结果统一提示未确认，不直接判断违规；重建输入组件恢复草稿并支持同值重试，仍仅在 pass=true 时提交。
- 新页面进入需要网络读取资料 → 加载态和错误重试明确展示，未完成读取前禁用编辑。
