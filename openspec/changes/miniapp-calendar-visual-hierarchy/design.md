## Context

当前 `miniapp/pages/calendar/` 的月历下方是一张同时包含所选日期、服务端通用宜忌和本人事项提示的卡片。真实宜忌数组及本人事项数组均可较长，需要在保持宜忌完整可见的前提下减轻视觉噪声，并精简个人提示。下方另有择日入口及日期资料。现有页面已有未提交修改；日期选择、真实接口、个人结果和演示分支必须保留。

## Goals / Non-Goals

**Goals:** 月历和所选日期形成清楚的阅读主线；所选日期的宜忌全部直接可见，个人事项保留摘要与详情；真实、通用和演示来源仍清晰；窄屏可读可点。

**Non-Goals:** 修改历法、宜忌或本人事项规则；增加接口或新页面；改变日期选择和请求时序；整体重做其他小程序页面。

## Decisions

### 1. 月历保持完整七列，减少装饰竞争

保留月份导航、今天按钮、农历/节气、今天和选中态。日期数字为主，农历文字为辅；今天与选中同日时只保留一组清楚的强调，不再叠加多个高对比徽标、边框和底色。月历仍支持跨月日期点击。页面主要间距采用少数统一档位，卡片边界和浅色底块只用于区分主次，不以缩小字号换取容纳量。

### 2. 所选日期完整展示通用宜忌

日期标题和农历/节气构成卡片顶部。通用宜、忌直接遍历服务端返回的完整原始数组，不做数量截取、剩余项计数或展开/收起。标签使用低装饰的换行排版，长中文词组允许自然换行。空数组、加载与失败均独立呈现，绝不把缺失资料当作“无宜忌”。换日时清掉旧日期结果，沿用请求序号和日期校验，避免异步响应期间混用日期。

### 3. 本人提示保持一条摘要，完整内容进入既有详情

已绑定时显示“本人命盘”来源、一个可理解的状态或首条事项短摘要，以及现有详情入口；若有更多事项，标明数量，不在日历重复铺开每条来源和依据。无特别事项、依据不足、加载和失败分别显示明确状态。未绑定时以“选择本人命盘”为主要操作，示例体验用次要入口并持续标为演示。演示结果也只露出一条摘要。通用宜忌与本人提示保留独立标题，避免将通用标签误认作个人结论。

### 4. 次级内容保留路径，视觉验证以真实画面为准

择日入口仍只有一处；日期资料和 24 节气仍在后方，可正常切换。沿用项目 CSS Variables/小程序 WXSS 风格，不引入组件库。页面检查覆盖完整宜忌、换日清空和各状态；微信开发者工具或真机核查 4/5/6 周月份、窄屏长标签、未绑定/绑定及底部 Tab。如无法取得画面，记录未验证项，不把代码检查当作视觉验证。

## Risks / Trade-offs

- [完整宜忌在数据多时增加卡片高度] → 保持标签排版轻量、自然换行，个人事项只保留摘要，不截断宜忌内容。
- [压缩个人信息造成结论过度简化] → 摘要使用既有状态/事项文案，明确“本人命盘”来源，详情继续展示依据。
- [切日后仍显示上一个日期的宜忌] → 选日时同步清空旧结果，沿用现有请求 ID 和日期校验。
- [视觉调整在窄屏出现截断] → 用真实小程序画面检查长标签、节气和日期格；不要用隐藏溢出替代可读排版。
- [覆盖现有未提交修改] → 实施前逐项查看日历文件差异，以工作区内容为基线最小化修改。

## Migration Plan

仅调整小程序日历页面和相应检查，无数据迁移。回退页面布局即可，现有接口与详情路径兼容。

## Open Questions

具体字号与留白数值以开发者工具或真机截图确认；提案固定信息层级和宜忌完整展示行为，不预设单一设备尺寸。
