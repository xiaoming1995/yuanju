## Context

“我的”页已通过 `api.profile()` 和 `api.personalChart()` 展示账户、最近排盘及本人命盘；资料编辑在独立页面，历史和绑定本人命盘在首页历史态。当前页还保留重复历史入口、四个仅弹出“尚未接入”的工具、带前置图标的设置列表及临时“隐私政策”弹窗。用户确认的静态设计稿采用暖白背景、轻卡片、更多留白和少量金色操作提示；图片中的昵称、记录及命盘日期均为示例。

## Goals / Non-Goals

**Goals:**

- 让资料、本人命盘、排盘记录、设置与帮助按重要性自然排列，卡片与字号跟随小程序首页的克制风格。
- 合并重复入口，只展示当前真实可完成的操作，并保持现有登录、资料编辑、历史、本人命盘、网页账号绑定和退出登录路径。
- 让不同登录、记录和网络状态下的布局与提示准确、可读。

**Non-Goals:**

- 不新增意见反馈、分享、公众号、客服、正式隐私政策或账号注销能力。
- 不改动后端接口、数据库、用户身份合并规则或本人命盘主动绑定规则。
- 不按静态稿硬编码示例用户、数量、命盘或日期。

## Decisions

### 1. 以页面局部样式完成视觉收敛

只调整 `miniapp/pages/mine/index.wxss`，复用全局暖白底色、文字色和轻量卡片语汇；不修改 `app.wxss`，避免影响首页、日历和结果页。参考首页现有的约 22rpx 卡片圆角和轻阴影，以留白、字重及细分隔线建立层级。保留金色给可操作文字和本人命盘的小面积标识，减少大面积深色、彩色图标和重复装饰。

### 2. 一张卡片承载排盘摘要

在 `index.wxml` 将总数、最近两条和“查看全部”合并为“我的排盘”卡片，移除设置列表里的“查询历史”。保留最近记录整行点击和进入历史页的现有导航；零记录时在同一区域显示创建排盘的明确引导。避免增加新的记录筛选和详情路由。

### 3. 设置区仅展示真实动作

移除四个尚未接入的常用工具和相应样式；“演示数据说明”也不再占用“我的”页入口，具体演示提示仍留在对应功能页。将网页账号绑定、隐私说明和关于缘聚放入无前置图标的“设置与帮助”列表。未绑定网页账号时沿用现有展开表单和绑定请求；已绑定时展示邮箱状态，不显示可点击箭头。退出登录继续独立放在列表下方。正式隐私政策未接入前，把现有临时弹窗标为“隐私说明”，并保留内容的真实范围。

### 4. 状态变化保持页面稳定

页首资料区保持进入独立编辑页。本人命盘区复用现有读取、查看、去历史页选择和重试流程，但统一卡片边界与操作文案。`api.profile()` 失败时不能让旧统计和最近记录看起来像最新数据；页面显示可重试的错误提示。退出登录或令牌失效后隐藏用户数据。样式检查覆盖窄屏、长昵称、长记录名、已绑定邮箱和底部安全区域。

## Risks / Trade-offs

- [静态设计稿中的内容与真实数据不一致] → 页面从接口读取名称、数量、日期和绑定状态，视觉稿只作为排版参考。
- [移除工具入口降低功能可见度] → 这些入口当前无法完成操作；未来对应服务可用时再单独设计入口。
- [临时隐私弹窗仍不足以支持正式发布] → 本轮使用准确名称，正式政策作为独立发布事项处理。
- [合并历史入口后用户找不到完整列表] → 在记录卡标题右侧保留清晰的“查看全部”，最近记录仍可直达详情。

## Migration Plan

仅小程序前端页面变更，无数据迁移。发布前在开发者工具和真机检查各状态；若发生布局问题，可回退页面 WXML/WXSS/JS 修改，不影响后端数据。
